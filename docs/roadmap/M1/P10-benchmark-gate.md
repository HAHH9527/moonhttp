## 功能描述（speckit 输入种子）

交付 M1 的**可复现基准套件**与**性能门禁**，把宪法 II 落地为机制：
场景矩阵化基准程序（自建可控服务端驱动）、三基线对比臂、指标采集
（p50/p95/p99、req/s、native RSS）、M1 判据门禁（池化相对 churn ≥20×）、
历史基线归档防回归。本包是 M1 交付判据一（round2 基准复刻 ≥20×）的量化载体，
并为后续里程碑（M2 的 L5 syscall 门禁等）提供扩展位。

## 范围

包含：

- **基准服务端**：按 `examples/http_server_benchmark` 手法自建的高吞吐可控服务端
  （P03 夹具面向正确性、本包面向吞吐；宪法 I 不搬上游代码，README 差异 D8）。
- **场景矩阵**（14 §5）：
  - 连接形态 × {churn（每请求新连接）、单连接顺序复用、池 K∈{1,4,16,64}}；
  - 请求形态 × {GET、POST 定长（L2 生效）、POST chunked、上传 1MB}；
  - 内容 × {gzip 响应开/关（若 P03 C4 结论需要）}。
- **三对比臂**：
  1. moonhttp churn 臂（禁用池/每请求新连接的对照实现）；
  2. **async/http 单连接复用臂**（纯 `@http.Client` 顺序复用，宪法 II 指定的
     moonhttp 价值对比基线）；
  3. moonhttp 池化臂（正式路径）。
- **指标**：p50/p95/p99 延迟、req/s、（native）进程 RSS 曲线、长跑（≥10k 请求）
  的池守恒/fd 稳定。
- **门禁**：池化臂 vs churn 臂 **≥20×**（M1 判据；round2 实测 47–56×，门槛留
  抖动余量）；门禁脚本输出通过/失败判定。
- **基线归档**：每次运行产出机器可比对的结果文件（JSON/CSV）入库
  `docs/benchmarks/`（或 plan 另定），作为 moonhttp 自身历史基线（宪法 II：
  「保留 moonhttp 自身历史基线防回归」）。
- **报告模板**：M1 性能报告（数据表 + 环境说明 + 与 round1–3 的对照结论）。

非目标（显式排除）：

- 真实网络延迟分层（1ms/30ms/100ms，14 §5 项——M1 以 loopback 与 round1–3 可比
  为准，分层随 M2/M3 需要引入）；100MB 上传与 syscall 计数门禁（L5 属 M2 上游
  PR 包）；CI 硬门禁的自动化接入方式（本地脚本先交付，CI 接入在 plan 定，
  澄清 C2）；wasm-gc/js 基准（D9）。

## 用户故事种子

### US-1 场景矩阵一键运行（P1）

作为维护者，我一条命令跑完场景矩阵，得到各场景的延迟/吞吐/RSS 指标表。

**独立测试**：套件自身冒烟（缩小规模跑通全矩阵场景）。

**验收场景**：

1. Given 基准命令（含规模参数），Then 产出全部「连接形态 × 请求形态」组合的
   指标，无场景缺失。
2. Given 相同环境连续运行两次，Then 同场景指标波动在记录的噪声带内（可复现性）。

### US-2 三臂对比与 ≥20× 门禁（P1，M1 判据）

作为维护者，门禁脚本对比三臂并给出通过/失败：池化臂相对 churn 臂 ≥20×。

**验收场景**：

1. Given 全量运行，Then 报告含三臂对比表，且池 K=16 臂 vs churn 臂的
   p50 加速比 ≥20（预期 47–56×，round2 对照）。
2. Given 人为劣化（如池禁用开关），Then 门禁判定失败（门禁确实有效）。

### US-3 async/http 基线对照（P1，宪法 II）

作为维护者，报告以 async/http 单连接复用为对比基线呈现 moonhttp 的增量价值
（池化并发 vs 顺序复用的差距）。

**验收场景**：

1. Given 三臂数据，Then 报告含「池 K=16 vs async/http 顺序复用」的加速比
   （round2 对照：178–196µs vs 415–431µs，约 2.1–2.4×）与结论陈述。

### US-4 长跑与资源稳定（P2）

作为维护者，≥10k 请求长跑场景验证池守恒与 fd/RSS 稳定。

**验收场景**：

1. Given 池 K=16 + 10k 请求长跑，Then 池内计数守恒、（native）fd 数平台化
   不增长、RSS 增长有界并记录曲线。

### US-5 基线归档与回归比对（P2）

作为维护者，历史结果入库后可与当前运行自动比对，回归超阈值告警。

**验收场景**：

1. Given 归档基线与当前运行，Then 比对输出各场景 delta；构造一次人工回归
   （插 sleep），Then 告警触发。

## 边界用例

- 规模参数下界（请求量太小统计不稳定的保护/警告）；服务端成为瓶颈的识别
  （服务端 CPU 饱和时标注「服务端受限」而非误判客户端回归）；loopback 噪声
  （后台负载敏感——报告记录环境与运行次数中位数策略）；gzip 场景的解压 CPU
  归因（区分传输与解压耗时，若纳入）。

## 需求种子

- **FR-001** 基准 MUST 一键运行且场景矩阵无缺项。
- **FR-002** 门禁 MUST 判定「池化 vs churn ≥20×」并可用于回归拦截。
- **FR-003** 报告 MUST 含 async/http 单连接复用基线臂（宪法 II）。
- **FR-004** 结果 MUST 机器可比对（结构化格式）并归档为历史基线。
- **FR-005** 长跑场景 MUST 断言池守恒与 fd 稳定（native）。
- **FR-006** 基准代码 MUST 与库代码分离（独立目录/程序，不进 src 公开面）。

## 关键设计要点

- 方法论对齐 round1–3（loopback、同款指标口径），目标值以其报告数字为参考
  （10,029–10,047µs / 415–431µs / 178–196µs@K=16）。
- churn 臂实现：正式池 + 强制不归还（或独立每请求 connect/close 路径），
  plan 定；必须走 moonhttp 正式管线而非旁路，否则对比失真。
- 指标统计：每场景多次运行取中位数（噪声带记录），分位数基于单请求计时样本。
- 门禁阈值 ≥20× 已含 47–56× 实测的余量；更细的回归阈值（如 ±15%）用于
  US-5 的历史比对而非硬门禁。

## 侵入性与宪法合规

- 非侵入（基准侧）；不搬上游基准资产（D8）。
- 宪法 II 的直接落实：性能数据随改动附带（M1 收口报告）、实测杠杆不回归
  （门禁）、async/http 复用为对比基线（三臂设计）。
- 宪法 IV：基准全部基于本地可控服务端。

## target 矩阵

| target | 支持 | 说明 |
| --- | :-: | --- |
| native | ✅ | 主基准 target（含 RSS/fd） |
| wasm | ✅ | 同矩阵可跑（moonrun 宿主），指标口径记录差异；RSS/fd 项以池守恒代替 |
| js | ⭕ | 无池语义，仅 churn/复用两臂无意义——不跑，降级清单记录 |
| wasm-gc | ❌ | 上游 runtime 缺口 |

## 性能影响

本包即性能交付物；不改变库运行时代码（若发现热点，走对应包的 spec 变更流程
而非在基准包内顺手改库）。

## 测试方案

- 套件冒烟（缩小规模全场景跑通）入常规测试；全量基准与门禁为显式命令
  （不入常规 `moon test`，避免拖 CI）。
- 门禁有效性用「人工劣化触发失败」自证（US-2 场景 2）。
- native + wasm 双 target 冒烟。

## 澄清问题种子

- **C1** 门禁接入形态：本地脚本 vs CI 定时任务 vs 手动里程碑检查（宪法仅要求
  数据附带与不回归——M1 先手动/脚本，CI 化时机用户裁定）。
- **C2** 归档位置与格式（`docs/benchmarks/m1-*.json` vs 独立目录；仓库体积考量）。
- **C3** churn 臂的实现口径（正式管线强制 churn vs 独立对照实现——保真 vs 隔离
  的取舍，plan 定）。
- **C4** gzip 场景是否入 M1 矩阵（与 P03 C4 联动；@http 透明解压的 CPU 归因
  需可分离才纳入）。
- **C5** wasm 基准的宿主计时口径（moonrun 计时与 native 可比性声明）。

## 验收判据（包级 DoD）

1. US-1–US-3 验收场景通过：全矩阵可运行、三臂对比报告产出、≥20× 门禁判定
   有效（含人工劣化自证）。
2. M1 判据一在本包闭环：正式报告归档（数据 + 环境说明 + round1–3 对照结论）。
3. 长跑与归档比对（US-4/5）按 plan 范围交付（若 C1 裁定 M1 仅手动，则至少
   交付长跑场景与归档文件）。
4. `moon info && moon fmt` 干净（基准代码独立目录，不污染 src `.mbti`）。
