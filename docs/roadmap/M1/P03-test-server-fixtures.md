# P03 可控服务端测试基建

> 里程碑：M1 性能核心（及 M2–M5 复用的地基）｜ 前置依赖：无 ｜ 人力估计：~1 人日
> 来源：`proj-init-docs/okhttp-on-async-http/` 各篇 §8 测试方案的公共前置；
> 宪法 IV「网络行为测试必须基于可控本地服务端，不得依赖外部网络环境」。
> 侵入性：非侵入（仅 `@http.Server`/`@socket` 公开 API）｜ 建议特性 slug：`m1-p03-test-fixtures`

## 功能描述（speckit 输入种子）

交付 moonhttp 自有的**可编程本地测试服务端夹具库**，作为 M1 全部网络行为测试
（定长帧字节断言、重定向决策表、stale-retry 故障注入、超时触发、池并发正确性）
与 P10 基准的统一底座。两类夹具：

1. **脚本化 HTTP 服务端**（基于 `@http.Server`）：路由级可编程行为——
   延迟响应头/延迟体/慢速滴流（滴流间隔可调）、重定向链（任意跳数与状态码
   301/302/303/307/308 + 任意 Location，含相对/绝对/畸形）、echo 回显
   （每请求唯一 id 注入 body，供响应体串号检测）、定长/chunked 响应可选、
   `Connection: close` 头、gzip 响应、401/407 挑战（M2 备用）。
2. **裸 TCP 脚本对端**（基于 `@socket`）：接受连接后立即 close/RST、
   回半截响应头后断、**原始字节捕获**（把收到的请求字节完整留存供断言——
   定长帧/头折叠的线上字节验证）。

附测试驱动辅助：随机端口分配、夹具生命周期（启动/停止/超时保护）。

宪法 I 约束：不搬运上游 async 仓库的 `test_programs`/`examples`/`mio` 资产
（README 差异 D8），手法对齐、代码自建。

> **既定事实登记（2026-10-16，P02/T009 先行落地实测，作为本包 specify 种子）**：
> 第 2 类夹具中的「原始字节捕获」已在 `src/fixtures` 落地（`RawPeer` 捕获

> 附自证元测试），且 native + wasm 双 target 可跑（wasm 侧由 moonrun/WASI
> 宿主提供平台专用 socket 导入，`moon test --target wasm` 实测全绿、捕获
> 端口逐次不同；口径见 spec 002 A8 方案 c 回写）。P03 的 specify/plan 以此
> 为既有底座，不必从零起；第 1 类脚本化 HTTP 服务端与第 2 类其余行为
> （close/RST、半截响应注入、慢速滴流等）仍待 P03 交付。夹具宿主位置是否

## 范围

包含：

- 夹具库包（位置在 plan 阶段定：独立测试支撑包或样例目录）。
- 上述两类夹具的全部行为脚本与驱动辅助。
- 每种行为一个自证用例（夹具的「元测试」：证明夹具确实产生预期行为）。

非目标（显式排除）：

- TLS/https 夹具（M3/07 需要时扩展；M1 全部场景 loopback 明文 http）；
- 外部网络依赖、真实互联网地址（宪法 IV）；
- 性能压测服务端的高吞吐优化（P10 基准若需专用服务端，在 P10 内按
  `examples/http_server_benchmark` 手法自建，不与本库耦合）；
- HTTP/2 服务端（M6）。

## 用户故事种子

### US-1 脚本化 HTTP 场景（P1）

作为 M1 各特性的测试编写者，我启动一个行为可脚本化的本地 HTTP 服务端，
按路由返回可编排的响应（延迟/重定向/echo/压缩/连接关闭头）。

**独立测试**：夹具元测试 + 用 `@http.Client` 原语直连夹具验证行为。

**验收场景**：

1. Given 路由 `GET /slow` 配置「延迟 300ms 后回响应头、body 再滴 3 块、每块间隔
   100ms」，When 直连请求，Then 观测到响应头时延与 body 到达间隔符合编排。
2. Given 重定向脚本 `[301→/a, 302→相对 ../b, 303→绝对 http://127.0.0.1:PORT/c]`，
   When 逐跳请求，Then 状态码与 Location 逐项符合。
3. Given echo 路由，When 并发 N 个带唯一 id 的请求，Then 每个 body 精确回显
   自身 id（串号检测的判据来源）。

### US-2 裸 TCP 故障注入（P1）

作为 stale-retry/取消/超时的测试编写者，我用裸 TCP 对端注入网络级故障：
接受后立即断开（模拟陈旧连接被静默关闭）、回半截响应头后 RST、慢速接收。

**验收场景**：

1. Given 「accept 后立即 close」脚本，When 客户端在复用连接上发请求，
   Then 客户端收到 EOF/ReaderClosed 类错误（为 P07 提供判据）。
2. Given 「回 15 字节状态行片段后断」脚本，When 请求，Then 客户端在读响应头
   阶段失败且未解析出完整状态行（P07 的「不可重试」分支判据）。

### US-3 原始字节捕获（P1）

作为定长帧/头折叠的测试编写者，我用捕获型 TCP 对端拿到客户端发出的
原始请求字节，逐字节断言线上形态。

**验收场景**：

1. Given 捕获对端，When 发送定长 POST，Then 捕获字节可解析出
   `Content-Length` 头且不含 `Transfer-Encoding`（P02 US-2 的判据来源）。
2. Given 捕获对端，When 同一请求重放两次，Then 两次捕获字节逐字节相同
   （重放一致性的判据来源）。

### US-4 慢速滴流参数化（P2）

作为超时特性的测试编写者（P08），我配置「持续但慢速滴数据的 body」，
以验证 read 超时的按操作重置语义。

**验收场景**：

1. Given 每 200ms 滴 1KB、总时长 3s 的 body，When read_ms=1000 的按操作超时，
   Then 不触发超时（每块间隔 < 超时阈值）——本夹具用原生 @http.Client 预验证。

## 边界用例

- 端口耗尽/夹具端口冲突（自动重试分配）；夹具停止时有在途连接（优雅关闭语义）；
- 捕获对端收到畸形请求字节（夹具不得 panic，如实留存）；wasm 宿主 socket 的
  RST 语义差异（03 特性文档 §5 wasm 行提示——夹具在 wasm 上的故障注入行为
  差异需显式记录，见澄清种子 C3）。

## 需求种子

- **FR-001** 夹具库 MUST 仅依赖 `@http.Server`/`@socket` 公开 API，零侵入。
- **FR-002** 每种行为 MUST 有自证元测试（夹具行为可判定，防夹具自身腐烂）。
- **FR-003** 全部夹具 MUST 仅监听 loopback，不触外部网络。
- **FR-004** 夹具生命周期 MUST 有超时保护，挂起不得拖死测试进程。
- **FR-005** 原始字节捕获 MUST 保序、保完整（不聚合丢失、不改动字节）。

## 关键设计要点

- 行为编排用声明式脚本（行为 enum/结构列表），避免每个测试手写过程式服务端。
- echo 的唯一 id 注入是 P04「并发正确性——响应体串号检测」的判据基础。
- 「半截响应头」的截断点参数化（状态行前/状态行后/头行中间），对应 P07 的
  可重试/不可重试分界。

## 侵入性与宪法合规

- 非侵入；宪法 IV 的直接落实（本包是「可控服务端全绿」判据的载体）。
- 宪法 I：不复制上游测试资产（README D8），spec 中注明手法参考来源。

## 性能影响

不适用（测试基建，冷路径，宪法 II 的简洁优先区）。

## 测试方案

自证元测试即本包测试（US-1–US-4 场景）；native + wasm 双绿。

## 澄清问题种子

- **C1** 夹具库宿主位置：`src` 内测试支撑包 vs 独立样例目录（moon 对测试专用包
  的发布语义）。
- **C2** `@http.Server` 与 `@socket` 在 js target 的可用性与形态（决定 js 退化方案）。
- **C3** wasm（moonrun 宿主）上 close/RST 的实际语义与 native 差异清单
  （影响 P07 在 wasm 的故障注入断言强度，允许降级但须记录）。
- **C4** gzip 行为脚本 M1 是否需要（P10 基准矩阵含 gzip on/off 场景——若 @http
  透明解压已覆盖断言需求，可推迟）。
